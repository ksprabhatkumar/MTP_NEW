# Next experiment after the completed REALDISP Objective 1 run

## Decision from current evidence

Treat O1 as a documented negative result under the current model and protocol.
The residual graph does not improve recorded induced displacement over the
no-graph control. Keep the 118 completed jobs and their locked code/data snapshots
as the baseline. The next scientific question is whether orientation-stable
features can reduce the recorded placement loss (O2), and whether the dynamic
graph uses those features in a meaningful way. Do not simply repeat the same
53-epoch residual training.

The complete quantitative analysis is in
`results/o1_full_20261016_220301/ANALYSIS.md`. Its CSVs are generated by
`analyze_o1_results.py`; original checkpoints/predictions are unchanged.

## Step 1: close data and measurement gaps without training

1. Verify REALDISP sensor/channel order, units, label mapping, timestamp
   continuity, and missing values for every recording against the dataset manual.
   Pay special attention to subject 7's ideal file (three classes, 238 windows),
   subject 6's 21-class ideal file, and subject 15 mutual4 (near-zero F1).
   Document whether missing classes reflect the raw files rather than a parser
   error. Do not silently impute unrecorded activities.
2. Tabulate per-subject, per-recording and per-class sample counts. Report both
   fixed 33-class macro-F1 and F1 over classes present in the compared
   recordings; label the denominator of every table. Do not treat overlapping
   windows as independent test subjects. For displacement severity, compare
   models within each exact recording and supported class set; activity mix and
   duration vary across the 4/5/6/7 files.
3. Audit the existing graph with no retraining: effective physical/global/dynamic
   contribution after final row normalization; per-window adjacency variation;
   scenario changes; gradient norms; and an inference intervention replacing
   dynamic affinity with a uniform off-diagonal row while preserving the
   physical/global branches. A negligible prediction change would show that
   this fitted model barely uses its dynamic branch. Inspect several
   subject/seed checkpoints, not one heatmap.

Gate: the data parser and class accounting must pass before new training. If a
raw-data defect is found, fix it and rerun the affected O1 controls first.

## Step 2: implement the smallest Objective 2 feature comparison

Keep the O1 temporal backbone, graph layer, classifier, optimizer, window size,
subject splits, and compute budget fixed across the new feature variants.

- Raw six-axis acc/gyro input: rerun under the new common validation rule so
  comparison to O2 is fair.
- Magnitudes: acceleration norm and gyroscope norm per IMU and timestep.
- Magnitudes plus within-IMU dot products: accel dot gyro, accel dot its
  preceding timestep, and gyro dot its preceding timestep (five scalars total).
  Define the first timestep's lag convention in advance.
- Raw-axis SO(3) augmentation control: apply one independent 3D rotation per
  sensor/window to both its acc and gyro vectors before normalization.

Cross each representation/control with no cross-sensor graph and the existing
residual graph. This shows whether a gain comes from the feature representation
or its interaction with routing. Form invariant features from raw physical
units before fitting training-only scalar normalization; do not independently
normalize x/y/z first. Keep sensor identity and sensor availability separate.

Numerical gate before training: draw independent fixed rotations for each
sensor; require magnitude/dot features, their normalized values, and model
predictions in evaluation mode to agree within a declared floating-point
tolerance. Raw-axis augmentation has no mathematical invariance guarantee and
is judged empirically.

Train only on ideal recordings of source subjects. Use a distinct validation
subject with adequate class coverage, including its ideal and self-placement
recordings. Lock the checkpoint criterion before training (for example,
equal-weight ideal/self macro-F1 over the same supported classes, with an ideal
performance floor). Do not select models using the held-out subject's induced
scores. Fix seeds, epochs, batch size and candidate list from source-side
validation. Then evaluate the three held-out subjects (2,5,15), three seeds,
recorded induced files 4-7 separately, synthetic rotations separately, and
ideal/self placement. Supplement with ideal LOSO across all 17 subjects using
one seed, reporting subject 7's thin coverage explicitly.

Because this completed O1 analysis already exposed all three subjects' induced
results, any subsequent design on the same three subjects is exploratory.
Strong confirmatory claims need another independent recorded-displacement
cohort or a prospective collection. DSADS can support synthetic-rotation
generalization, but it cannot substitute for recorded physical displacement.

## Step 3: only if graph evidence justifies it

If O2 improves both graph and no-graph models equally, report a feature benefit
without crediting dynamic routing. If adaptive routing remains weak, test one
separately labeled O1 architecture revision: compute query/key affinity from
learned per-sensor temporal descriptors; row-normalize each graph branch before
mixing; and log effective branch mass and prediction sensitivity. Compare this
revision with the same no-graph/fixed controls under the O2 feature protocol.
Do not change feature representation and graph design in a single unablated
experiment.

Only after O1/O2 choices are locked should the planned O3 subject-client
federated simulator begin. It needs centralized, local-only and FedAvg controls,
an explicit shared/local normalization policy, separate unseen-user and
known-client evaluations, and communication/training-cost logs.

## Deliverable and acceptance rule

Produce a versioned configuration, split manifests, tests for rotation
invariance and subject separation, per-epoch logs, best checkpoints, raw
predictions, per-class/recording metrics, seed/subject variation, routing
diagnostics and batch-one cost. An O2 benefit must exceed seed/subject variation
and the raw-axis augmentation control without an unacceptable ideal-placement
loss. If it does not, preserve and report the negative result.
